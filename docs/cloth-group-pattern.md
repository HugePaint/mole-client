# 破解 `resource/cloth/bmpswf/<组>/<衣服ID>.swf` 的组号规律

> 问题：衣服**图标**（`resource/cloth/icon/<id>.swf`）可以从博物馆的 `ClothJson[].path` 直接拿到，
> 但衣服**位图**多了一层 `<组>` 目录，组号来源不明 —— 静态爬取因此卡在 42 个文件。
> 结论：**组空间恰好是 `{1001, 1002, 1003}`，且任意存在的衣服 ID 在这三组里各有一份位图。**
> 成果：衣服位图从 **77 → 11,178 个**。

---

## 一、初始观察

游玩时抓到的 77 个文件里只出现了两个组：

```
组 1001: 48 个（含 1.swf、2.swf 两个非数字名）
组 1002: 29 个（含 1.swf、2.swf）
```

两组的 ID 集合**大量重叠**（22 个共同 ID），例如 `12052` 在 1001 和 1002 里都有。
这说明**组号不是衣服 ID 的函数**——同一件衣服在不同组里各有一份。

---

## 二、第一个假设（被数据否掉）

博物馆 `suitlist` 里每个衣服条目带 `typeid` 字段，于是提出：

> 假设 A：组号 = 1000 + typeid

工具 [`tools/cloth-group-analysis.js`](../tools/cloth-group-analysis.js) 做的对照结果：

```
博物馆衣服条目: 1433
typeid 分布: 1=1287, 49=156        ← 只有两种 typeid

假设「组号 = 1000 + typeid」验证:
  吻合:   11
  不符:   14
  ID 不在博物馆数据里: 52
```

反例很直接：`12052` 实际在**组 1002**，但 typeid=1 → 预测 1001。
而且同一组 1001 内 `typeid1` 有 11 个、`typeid49` 有 2 个，**并不恒定**。

**假设 A 否掉。** 顺带暴露了一个更重要的事实：
**77 个本地 ID 里有 52 个不在博物馆数据中** —— 博物馆的 1433 个衣服 ID 只是子集。

---

## 三、换成系统探测

既然类型学推不出来，就直接**探测组空间**：固定一个已知存在的 ID，扫一遍候选组号。

```
组 1000  -> 404
组 1001  -> 200  (  31,754 B)
组 1002  -> 200  (  37,593 B)
组 1003  -> 200  (  97,591 B)     ← 之前从没抓到过
组 1004  -> 404
组 1005  -> 404
组 1010  -> 404
组 1100  -> 404
组 2000  -> 404
组 1 / 2 / 3 / 100 / 999 -> 404
```

扫描范围 `1000..1020 + {1050,1099,1100,1200,2000,1,2,3,100,999}`，
**只有 1001、1002、1003 命中**。

再验证「是否每个 ID 在三组里都有」：

```
ID 12052 : 1001=OK  1002=OK  1003=OK
ID 12053 : 1001=OK  1002=OK  1003=OK
ID 18116 : 1001=OK  1002=OK  1003=OK
```

**规律成立。**

---

## 四、最终规律

```
resource/cloth/bmpswf/<组>/<衣服ID>.swf
                        │
                        └── 组 ∈ {1001, 1002, 1003}   固定三组
         <衣服ID> ∈ 全部存在的衣服 ID
```

- 组号**与衣服属性无关**，是三个固定的枚举值（很可能是三种体型/性别变体）。
- 每组里都有 `1.swf` 和 `2.swf` 两个非数字名文件（基础身体）。
- 缺的是「衣服 ID 全集」，而不是「组号规律」。

---

## 五、衣服 ID 全集从哪来

博物馆只给了 1433 个，不够。答案在用户提供的语料里：
**`52摩尔共享素材与数据/摩尔素材福利袋 By：52摩尔.rar`** 的 `衣服\` 文件夹

```
摩尔素材福利袋\衣服\12001.swf
摩尔素材福利袋\衣服\12002.swf
...

→ 3837 个按衣服 ID 命名的文件（12001 .. 15999）
```

**关键认识：清单里的文件名本身就是 ID，不需要解压 933 MB 的内容。**
我们要的是「有哪些 ID」；具体文件仍从官方 CDN 抓（那是权威且在役的版本）。

工具 [`tools/extract-corpus-ids.js`](../tools/extract-corpus-ids.js) 从 7z 的归档清单
（`7z l -sccUTF-8`）里抽出全部 ID 空间：

| 分类 | ID 数 | 范围 |
|---|---|---|
| **衣服** | **3837** | 12001 .. 15999 |
| 地图 | 244 | 14 .. 327 |
| BGM | 155 | 001 .. 363 |
| 家具 | 1401 | 160001 .. 161509 |
| NPC | 564 | 10000_1 .. 10311_1 |
| 拉姆用具 | 104 | 180001 .. 180115 |
| 牧场动物 | 123 | 1270001 .. 1270176 |

其中 **2564 个衣服 ID 是博物馆没有的**。

> ⚠️ 踩过的坑：7z 的清单被 PowerShell 的 `>` 重定向写成了 **UTF-16LE**
> （PS 5.1 的 `Out-File` 默认编码），Node 按 UTF-8 读会得到乱码、匹配全空。
> 已改为按 BOM 自动判定编码。

## 六、执行结果

把 `3837 × 3 = 11,511` 条候选 URL 加进爬虫（[`tools/crawl-resources.js`](../tools/crawl-resources.js)）：

```
种子 15665 条
  进度: 已请求 15665 | 200=14643 404=1021 err=1
  抓取 929.57 MB，队列耗尽
  命中率 93.5%
```

衣服位图抓取结果：

| 组 | 文件数 |
|---|---|
| 1001 | 3,728 |
| 1002 | 3,729 |
| 1003 | 3,721 |
| **合计** | **11,178** |

覆盖率 ≈ 11,178 / 11,511 = **97.1%**。未命中的约 330 个分成两类：
- 在 2015 年语料里存在、但**线上已下架**的衣服 ID
- 源站返回 **200 + 空 body** 的 ID（见下）

---

## 七、附带发现：源站对部分资源返回「200 + 空 body」

对比语料与线上文件时发现缓存里有 **260 个 0 字节文件**，直连源站验证确认**不是镜像的问题**：

```
[200] len=       0  resource/cloth/bmpswf/1001/13686.swf
[200] len=       0  resource/cloth/bmpswf/1001/15250.swf
[200] len=   31754  resource/cloth/bmpswf/1001/12052.swf     ← 正常对照
```

这些资源**存在于 ID 空间，但在当前 CDN 上是空的**。

镜像已修正：对 0 字节的 200 响应打 `empty: true` 标记，
并新增 `/__empty` 接口（`?tsv` 可导出），使统计不再把它们混进正常资源。

按目录分布：`resource/cloth` 254、`resource/map` 2、`resource/dragon` 2、`resource/task` 1、`resource/login` 1。

